
## ==Введение==
На базовом уровне разработка для платформы WebPartyTime сводится к описанию ==PartyFlow== по заданной спецификации - ==WebPartySpec==.


В качестве основы формата для описания сценариев применяется язык разметки [==TOML==](https://toml.io/en/).

## ==Пример==
Ниже приведён полный текст сценария для игры =="Угадай число"==:
```toml title="guessthenum.webparty"
start = "intro"

[intro]
    [intro.layout]
    type = "multimedia"
    title = "Угадай число"
    description = "Игра скоро начнётся"

        [intro.to.guess]
        timer = 30
        inputBased = true

[guess]
    [guess.layout]
    type = "multimedia"
    title = "Угадай число"
    description = "Угадайте число от 1 до 5"

    [guess.input]
    type = "text"
    timer = 30
    title = "Введите число от 1 до 5"
    description = "Введите вашу догадку"
    limits = ["1", "2", "3", "4", "5"]
    correct = "pick"

        [guess.to.end]
        inputBased = true
    
    [guess.overviewer]
    type = "winner"
    timer = 5
```

Далее этот пример будет использован для объяснения основных принципов написания ==WebPartySpec==.

!!!note ""
    При загрузке сценариев через веб-интерфейс платформы название файла не имеет значения, однако для удобства файлы сценариев WebPartyTime принято создавать с расширением ==.webparty==

## ==Основы==
### ==Общая структура==
Поля на корневом уровне используется для задания ==общей информации PartyFlow==:
```toml
start = "intro" # Начать с узла intro 
```

Каждый вложенный в корень ==элемент словаря== считается за объявление отдельного ==PartyQuery==:
```toml
[intro] # Очередной PartyQuery
```

С помощью ==подсловаря layout== выбирается ==раскладка== (или =="интерфейс"==) на стороне ведущего. Внутри указываются актуальные для её отображения данные (затем поля передаются в веб-приложение для отображения):
```toml
    [intro.layout]
    type = "multimedia"
    title = "Угадай число"
    description = "Игра скоро начнётся"
```

!!!note ""
    Горизонтальные отступы опциональны, однако их применение делает сценарий более читаемым.

==Вложенный подсловарь to== используется для задания ==условий перехода== от данного узла к узлу, указанному после ==to==:

!!!note ""
    Можно устанавливать множество условий для перехода. В этом случае переход срабатывает при соблюдении ==любого из них==.
```toml
        [intro.to.guess]    # Переход от intro к guess произойдёт
        timer = 30          # По истечении таймера,
        inputBased = true   # Либо когда все участники отправили свой ответ
```

!!!note ""
    В любых блоках ==to==, ==overviewer== и ==vote== (см. далее) ==должно указываться хотя бы одно условие перехода==.

==Раскладку== для участников можно задавать через параметр ==input==:
```toml
    [guess.input]
    type = "text"                       # Формат ответа - текст
    correct = "pick"                    # Определить правильный ответ случайным выбором
    limits = ["1", "2", "3", "4", "5"]  # Из массива limits
    timer = 30
    title = "Введите число от 1 до 5"
    description = "Введите вашу догадку"
```

!!!note ""
    И в ==layout==, и в ==input== можно указывать ==timer==, тогда веб-приложение будет отображать пользователю обратный отсчёт определённого там числа секунд после получения соответствующих данных.

### ==Дополнительная структура==
Вид экрана результатов после получения обратной связи от участников задаётся ==необязательным подсловарём overviewer==:
```toml
    [guess.overviewer]
    type = "winner" # Отображать победителя только что завершившегося экрана
    timer = 5       # В течении 5 секунд
```

Если указывается тип правильного ответа (correct) =="pick"==, должен быть указан ==массив пространства выбора== случайного правильного ответа:
```toml
    type = "text"
    correct = "pick"
    limits = ["1", "2", "3", "4", "5"]
```

Если указывается тип правильного ответа (correct) =="vote"==, должен быть указан ==подсловарь vote==:
```toml
    [myquery.vote]
    type = "all"
    timer = 5
```
Он включает в себя тип голосования и условие перехода к следующему экрану после начала голосования.

### ==Завершение сценариев==
Для завершения сценария нужно указать переход к ==служебному узлу end==:
```toml
        [guess.to.end]      # Завершить сценарий
        inputBased = true   # Когда все участники отправят какой-либо ответ
```

### ==Порядок условий переходов==
Сначала ожидается срабатывание условия перехода к следующему узлу (указанное в ==.to==).

После этого ==PartyFlow== знает, куда будет осуществлён следующий переход, но в случае наличия ==vote== или ==overviewer== будет подставлять эти экраны с их условиями как промежуточные.

!!!note ""
    ==.to== -> (==.vote==) -> (==.overviewer==)

## ==Формат==
### Поддерживаемые ==корневые== значения
==start== - Точка входа PartyFlow (с какого узла начинать исполнение). ==Обязательный параметр.==

### Поддерживаемые значения ==layout==
==multimedia== - вывод на экран ==заголовка==, =основного текста== и ==изображения==:


* ==title== - текст заголовка
* ==description== - основной текст
* (Опционально) ==image== - URL изображения (доступного по сети)


==list== - вывод на экран списка пунктов:


* ==title== - текст заголовка
* ==points== - массив текстов подпунктов


==default== - вывод на экран =="Ожидайте запуска комнаты"==.

### Поддерживаемые значения ==input==

==text== - пользователи вводят ==текст==

* ==correct = "текст"== - считать правильным ответом данный текст
* ==correct = "vote"== - считать правильным ответом самый популярный в результате голосования пользователей

* ==correct = "pick"== - выбрать правильным случайный из пространства ответов
    * ==limits = ["текст1", "текст2", ...]== - ограничение пространства ответов


==number== - пользователи вводят ==число==

* ==(параметры аналогично text, только вместо строк вводятся числа)==


==choice== - пользователи выбирают из заранее заданных вариантов (==викторина==)

* ==limits = ["текст1", "текст2", ...]== - возможные варианты ответа
* ==correct = (число)== - считать правильным ответом вариант под номером (число)
* ==correct = "vote"== - считать правильным ответом самый популярный в результате голосования пользователей
* ==correct = "pick"== - выбрать правильным ответом случайный из возможных

!!!note ""
    Нумерация ответов идёт слева-направо и с единицы

### Поддерживаемые значения ==overviewer.type==
==all== - вывод на экран ответов сразу ==всех пользователей==


==winner== - вывод на экран =="победителя" данного экрана== и его ответа (где применимо)


==leader== - вывод на экран =="победителя" с учётом прошлых экранов сценария==

### Поддерживаемые значения ==vote.type==

==all== - все голосуют за лучший ответ

### Поддерживаемые условия ==to==
==timer== - переход по истечении определённого времени.


* Например, ==60== - через минуту

==inputBased== - перейти, когда все участники дали обратную связь.


* Если ==true==, условие сработает, когда все участники отправят ответ на сервер. 

###  ==Зарезервированные слова==
Рекомендуется не использовать следующие слова в качестве ==параметров== или ==имён узлов==, поскольку они могут конфликтовать с внутренними механизмами работы ==PartyFlow==:

!!!note ""
    ==overviewer, voting, vote, layout, type, input, to, correct, limits, start, end, step==


## ==Загрузка сценариев==
!!!note ""
    Эта функция только для авторизированных пользователей.

На главной странице WebPartyTime в разделе =="Создать комнату"== по кнопке =="плюс"== можно открыть меню загрузки сценария на платформу. 


При этом нужно будет ввести:

* ==Поля для карточки сценария== (как он будет отображаться в меню выбора сценариев и в комнате ожидания),
* ==Определить публичность== (должен ли сценарий отображаться всем во вкладке =="Публичные сценарии"==)
* ==Загрузить файл сценария==
* ==(Опционально)== Загрузить обложку для его карточки.
  
!!!note ""
    Впоследствии эти данные можно будет редактировать ==(кроме файла сценария)==.
