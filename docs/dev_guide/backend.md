# Backend
## ==Основы==
Большая часть взаимодействий осуществляется через единое ==Websocket-подключение==.


Каждая комната держит в памяти ==свой объект PartyFlow==, загружаемый при запуске комнаты.


При этом создание и запуск комнат производятся клиентом через ==RPC==.
==Там же можно добавить собственные условия и проверки ввода==:

```go
func createRoom . . .
    . . .

	partyFlow.AddInputChecker("text", input.GetTextChecker())
	partyFlow.AddCondition("timer", conditions.Timer, nil)
	partyFlow.AddCondition("inputBased", conditions.Input,
		map[string]any{"channel": room.GetInputReadyChannel()},
	)

. . .
```

!!!note ""
    Вторым аргументом в ==AddCondition== можно передать обработчику условия произвольный словарь для внедрения дополнительных аргументов.

==PartyFlow== включает в ход своего исполнения множество коллбек-функций, заполнением которых для пересылки данных клиентам занимается логика создания игровой комнаты:

- ==OnQuery func(*PartyQuery)== - Основная логика обработки и пересылки экранов пользователям 
- ==OnMove func()== - Вызывается прямо перед переходом к следующему узлу
- ==OnFinished func()== - Вызывается при завершении ==PartyFlow== независимо от причины
- ==OnGetVoteCandidates func(*PartyQuery) map[string]string== - Используется ==PartyFlow== для получения списка вариантов при голосовании, пересылающегося затем участникам
- ==OnGetWinners func(*PartyQuery) []string== - Используется ==PartyFlow== для получения списка победивших пользователей, чтобы вести их учёт и пересылать информацию ведущему

==Создание своего условия== заключается в написании функции, проверяющей условие ==асинхронно (в Goroutine)==, и возвращающей канал ==chan struct{}==, ==куда асинхронная функция должна подать сообщение в случае срабатывания условия==:
```go title="Простейшее условие (срабатывает тут же)"
func MoveConditionless(data any, args map[string]any) <-chan struct{} {
	channel := make(chan struct{}, 1)
	go func() {
		channel <- struct{}{}
	}()
	return channel
}
```

##  ==Структура файлов==
==./cmd/== - основная связующая логика (HTTP + Websocket)

- ==centrifuge_events.go== - Обработчики событий ==Centrifuge==
- ==rpc.go== - Обработчики основной логики RPC-вызовов
- ==routes.go== - HTTP-пути приложения

==./internal/== - основная бизнес-логика

- ==channels/== - вспомогательные функции для управления каналами ==Centrifuge==
- ==colors/== - объекты для цветного вывода в терминал
- ==conditions/== - стандартные условия перехода
- ==inputs/== - стандартные объекты для проверки ввода участников
- ==partyflow/== - логика парсинга и работы системы ==PartyFlow==
- ==room/== - основная логика для управления онлайн-комнатами

## ==API==
==/join -== Путь для подключения к ==WebSocket приложения==, региструющего пользователя в списке игроков и уведомляющего о глобальных изменениях на сервере независимо от действующей регистрации.

!!!note ""
    Подключение к комнате равносильно оформлению подписки на её ==Centrifuge-канал==.

==/auth -== По данному пути происходит авторизация на сервере, после чего становятся доступны функции загрузки сценариев игр на сервер и возможность присоединяться к комнатам только для авторизированных пользователей.

==/scripts -==  Этот путь позволяет загружать и получать информацию о сценариях
